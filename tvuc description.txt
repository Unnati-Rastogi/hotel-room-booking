# TVUC Smart Hotel Booking System --- Project Overview

This document provides a comprehensive, academic-level explanation of
the TVUC Smart Hotel Booking System. It breaks down the architecture,
database design, backend logic, and frontend user interface, making it
perfect for presenting the project to a teacher or evaluator.

## 1. Executive Summary

The TVUC Smart Hotel Booking System is a full-stack web application
designed to simulate a modern hotel reservation platform. It allows
users to view available rooms in an interactive 3D building model,
filter rooms based on preferences (e.g., sea view, suite, floor),
securely submit a simulated payment, and leave personalized
room-specific reviews.

**Primary Goals:** - Demonstrate CRUD (Create, Read, Update, Delete)
operations with a relational database. - Showcase a dynamic, single-page
application (SPA) frontend using vanilla web technologies without
relying on heavy frameworks. - Implement business logic such as payment
simulation, database triggers, and context-aware filtering.

------------------------------------------------------------------------

## 2. Technology Stack

The project follows a classic three-tier architecture (Client, Server,
Database): - **Frontend (Client):** Pure HTML5, CSS3, and Vanilla
JavaScript (`index.html`). No external UI frameworks (like React or
Bootstrap) are used, demonstrating a strong understanding of core web
fundamentals. - **Backend (Server):** Python with the Flask
micro-framework (`app.py`). It handles API routing, data validation,
business logic, and database communication. - **Database:** MySQL.
Relational data storage using `mysql-connector-python` to interface
between the Flask backend and the database.

------------------------------------------------------------------------

## 3. Database Architecture

The MySQL database (`hotel_booking`) is highly structured, utilizing
foreign keys, constraints, and triggers to maintain data integrity.

### Core Tables:

1.  **`rooms`**: The central inventory. Contains 50 pre-seeded rooms
    across 5 floors.
    -   Fields: `room_id`, `floor_number`, `room_number`, `room_type`
        (single/double/suite), `price`, `status` (available/booked),
        `view_type`, `smoking`, `balcony`.
2.  **`customers`**: Stores guest information.
    -   Fields: `customer_id`, `name`, `email`, `phone`.
3.  **`bookings`**: Links customers to rooms for specific dates.
    -   Fields: `booking_id`, `customer_id` (FK), `room_id` (FK),
        `check_in`, `check_out`, `booking_date`.
4.  **`payments`**: Tracks the financial transaction linked to a
    booking.
    -   Fields: `payment_id`, `booking_id` (FK), `amount`,
        `payment_status` (success/failed/advance/cash).
5.  **`reviews`**: Stores guest feedback, linked to specific rooms.
    -   Fields: `review_id`, `customer_name`, `rating`, `comment`,
        `room_type`, `view_type`, `room_number`, `review_date`.

### Advanced Database Features:

-   **Triggers:** A trigger (`trg_after_booking_insert`) automatically
    updates a room's `status` to 'booked' whenever a new booking record
    is inserted. This prevents double-booking and ensures data
    consistency without requiring a secondary update query from the
    backend.
-   **Indexes:** Strategic indexes on `room_id`, `check_in`,
    `check_out`, and `status` ensure fast query performance even as the
    table grows.

------------------------------------------------------------------------

## 4. Backend Logic (Flask API)

The `app.py` script serves as a RESTful API. It initializes the database
schema (auto-migrating if tables are missing) and exposes several
endpoints: - `GET /rooms`: Fetches all rooms and their availability
status. - `POST /book`: The core transaction endpoint. It: 1. Validates
dates and checks for existing overlaps. 2. Creates or fetches the
customer record. 3. Inserts the booking. 4. Simulates a payment gateway
(handles Full Payment, 30% Advance, or Cash at Hotel). 5. Inserts the
payment record. - `GET /bookings`: Retrieves a list of all active
reservations. - `GET /reviews`: Fetches guest reviews, with optional
query parameters to filter by `room_type` and `view_type`. -
`POST /review`: Accepts new guest reviews and stores them in the
database.

------------------------------------------------------------------------

## 5. Frontend UI & UX Features

The user interface is entirely contained in `index.html` and features
several advanced components:

-   **Interactive 3D Building:** Using CSS 3D transforms (`rotateX`,
    `rotateY`, `translateZ`), the rooms are mapped onto the faces of a
    3D rectangular prism. Users can toggle between the "Front" and
    "Back" of the building to visually browse rooms.
-   **Dynamic Filtering:** A control panel allows users to filter the 3D
    visualizer by Floor, View, Room Type, and Max Price.
-   **Booking Flow & Payment Modal:** When a room is selected, a sleek
    payment modal appears. It includes a simulated credit card that
    updates visually as the user types, and supports multiple payment
    methods (Full Card, 30% Advance, Cash).
-   **Context-Aware Reviews:** The review system is highly personalized.
    Reviews are tagged with specific room numbers, and when a user books
    a room, the "Leave a Review" form automatically detects their room
    number, view type, and room type, pre-filling the context for them.

## 6. How to Explain This to Your Teacher

When presenting this, focus on **data flow** and **state
management**: 1. **The Visuals:** Start by showing the 3D building.
Explain that the JS fetches data from `GET /rooms` and dynamically
renders HTML elements based on the room's status (`available` or
`booked`). 2. **The Logic:** Show the booking process. Explain that the
backend handles date validation and simulates a payment. Emphasize the
MySQL **Trigger**, which automatically marks the room as booked in the
database---teachers love seeing triggers because it shows advanced
database knowledge. 3. **The Personalization:** Show the review section.
Explain that the database schema was specifically designed to store
`room_number` so that future guests can read reviews specifically
tailored to the exact room they are booking.
